01 • FOUNDATION

Complexity Basics

2. Why Do We Need Complexity Analysis?

The same problem can have many different solutions.

For example, searching an element can be performed using:

Linear Search

10 20 30 40 50
         ↑

Check elements one by one.

Time complexity:

O(n)

Binary Search

If the array is sorted, we repeatedly divide the search area into two.

Time complexity:

O(log n)
For a very large input, O(log n) is much faster than O(n).

Therefore, complexity analysis helps us choose an efficient algorithm.

---

3. What is Input Size?

Input size is usually represented by:

n

Examples:

Array

int arr[n];
Input size = number of elements.
n = number of elements

Matrix

For an n × n matrix:
Input size ≈ n²

String

For a string:

"HELLO"

Input size:

n = length of string

---

4. What is an Operation?

An operation is a basic unit of work performed by a program.

Examples:

a = b + c;

Operations include:

  • assignment
  • addition
  • comparison
  • increment
  • memory access

We normally don't count every CPU instruction individually.

Instead, we analyze how the number of basic operations grows with input size.

02 • TIME ANALYSIS

Time Complexity

5. Time Complexity

Time complexity describes the growth of the number of operations performed by an algorithm as input size increases.

It does not necessarily mean actual clock time.

For example:

for(int i = 0; i < n; i++)
{
    printf("%d", i);
}

The loop runs:

n times

Therefore:

Time Complexity = O(n)

---

6. Best Case, Average Case and Worst Case

An algorithm can behave differently for different inputs.

There are three commonly discussed cases.

Best Case

Minimum amount of work.

Example: Linear search.

Array:

[10, 20, 30, 40, 50]

Searching for:

10

The first element matches.

Only one comparison is required.

Best Case = O(1)

---

Worst Case

Maximum amount of work.

If we search for:

50

we may need to check every element.

Worst Case = O(n)

If the element is not present, we also check all n elements.

---

Average Case

Expected amount of work over possible inputs.

For linear search, if the element is equally likely to be anywhere:

Average comparisons ≈ n/2

Since constants are ignored in asymptotic analysis:

O(n/2) = O(n)

Therefore:

Best Case    → O(1)
Average Case → O(n)
Worst Case   → O(n)

---

03 • ASYMPTOTIC ANALYSIS

Asymptotic Notations & Growth

7. Asymptotic Analysis

Asymptotic analysis studies the behavior of an algorithm when the input size becomes very large.

We are mainly interested in the growth rate.

Suppose an algorithm performs:

3n² + 5n + 10

operations.

For very large n, the n² term dominates.

Therefore:

3n² + 5n + 10 = O(n²)

We ignore:

  • constants
  • lower-order terms

---

8. Asymptotic Notations

The three important asymptotic notations are:

O
Ω
Θ

---

9. Big-O Notation — O()

Big-O represents an upper bound on the growth rate.

It is commonly used to describe the worst-case growth of an algorithm.

Example:

T(n) = 3n² + 2n + 5

The dominant term is:

n²

Therefore:

T(n) = O(n²)

Examples

5n + 10       → O(n)

2n² + 3n + 1  → O(n²)

10log n + 5   → O(log n)

100           → O(1)

---

10. Big-Omega — Ω()

Omega represents a lower bound.

It tells us that an algorithm requires at least a certain growth rate.

Example:

T(n) = 3n + 5

The growth is at least proportional to n.

Therefore:

T(n) = Ω(n)

---

11. Big-Theta — Θ()

Theta represents a tight bound.

If an algorithm grows both:

O(f(n))

and

Ω(f(n))

then:

Θ(f(n))

Example:

T(n) = 3n + 5

It grows linearly.

Therefore:

T(n) = Θ(n)

---

12. Difference Between O, Ω and Θ

NotationMeaning
O(f(n))Upper bound
Ω(f(n))Lower bound
Θ(f(n))Tight bound

Easy way to remember:

O  → At most
Ω  → At least
Θ  → Exactly the growth class

---

04 • COMPLEXITY CLASSES

Common Complexity Classes

14. O(1) — Constant Time

The amount of work does not depend on n.

Example:

int x = arr[0];

Only one array element is accessed.

Time Complexity = O(1)

Another example:

int sum = a + b;

O(1)

---

15. O(log n) — Logarithmic Time

The input is repeatedly divided into smaller portions.

Most common example:

Binary Search

Suppose:

n = 16

After each step:

16 → 8 → 4 → 2 → 1

Number of steps:

log₂(16) = 4

Therefore:

Binary Search = O(log n)

---

16. O(n) — Linear Time

Work increases directly with input size.

Example:

for(int i = 0; i < n; i++)
{
    printf("%d", arr[i]);
}

The loop executes n times.

Therefore:

O(n)

---

17. O(n log n)

Common in efficient sorting algorithms.

Examples:

Merge Sort
Heap Sort
Average-case Quick Sort

Example:

Divide the input → log n levels
Process n elements at each level

Therefore:

n × log n = O(n log n)

---

18. O(n²) — Quadratic Time

Usually occurs with nested loops.

Example:

for(int i = 0; i < n; i++)
{
    for(int j = 0; j < n; j++)
    {
        printf("*");
    }
}

Outer loop:

n

Inner loop:

n

Total:

n × n = n²

Therefore:

O(n²)

Bubble Sort is a common example.

---

19. O(n³) — Cubic Time

Three nested loops often produce cubic complexity.

for(int i = 0; i < n; i++)
{
    for(int j = 0; j < n; j++)
    {
        for(int k = 0; k < n; k++)
        {
            // operation
        }
    }
}

Total:

n × n × n = n³

Therefore:

O(n³)

---

20. O(2ⁿ) — Exponential Time

The amount of work doubles with each additional input element.

A classic example is naive recursive Fibonacci.

fib(n)
{
    if(n <= 1)
        return n;

    return fib(n-1) + fib(n-2);
}

Approximate complexity:

O(2ⁿ)

This becomes extremely slow for large n.

---

21. O(n!) — Factorial Time

Factorial complexity grows extremely quickly.

Example:

Generating all permutations

For n elements:

Number of permutations = n!

Therefore:

O(n!)

This is generally practical only for small input sizes.

---

05 • PROBLEM SOLVING

Loop & Program Analysis

23. How to Calculate Complexity of a Loop

Consider:

for(int i = 0; i < n; i++)
{
    printf("Hello");
}

Number of iterations:

n

Therefore:

O(n)

---

24. Two Separate Loops

for(int i = 0; i < n; i++)
{
    // O(n)
}

for(int j = 0; j < n; j++)
{
    // O(n)
}

Total:

O(n) + O(n)
= O(2n)

Ignore constant:

O(n)

Rule

Sequential operations are generally added.

O(n) + O(n²)
= O(n²)

The dominant term wins.

---

25. Nested Loops

for(int i = 0; i < n; i++)
{
    for(int j = 0; j < n; j++)
    {
        // operation
    }
}

Nested loops are generally multiplied:

n × n
= n²

Therefore:

O(n²)

---

26. Different-Sized Nested Loops

Consider:

for(int i = 0; i < n; i++)
{
    for(int j = 0; j < m; j++)
    {
        // operation
    }
}

Outer loop:

n

Inner loop:

m

Therefore:

O(nm)
Do not automatically write O(n²) unless:
m = n

---

27. Loop That Doubles

Consider:

for(int i = 1; i < n; i = i * 2)
{
    printf("%d", i);
}

Values:

1
2
4
8
16
32
...

The value doubles every iteration.

Number of iterations:

log₂ n

Therefore:

O(log n)

---

28. Loop That Halves

for(int i = n; i > 0; i = i / 2)
{
    // operation
}

Values:

n
n/2
n/4
n/8
...
1

Therefore:

O(log n)

---

29. Important Trick — Dependent Loops

Consider:

for(int i = 0; i < n; i++)
{
    for(int j = 0; j < i; j++)
    {
        // operation
    }
}

The inner loop does not always execute n times.

Total operations:

0 + 1 + 2 + 3 + ... + (n-1)

Using:

n(n-1)/2

We get:

O(n²)

---

30. Complexity of If-Else

if(condition)
{
    // O(n)
}
else
{
    // O(n²)
}

Worst-case complexity:

O(n²)

We select the branch with the greater growth rate for worst-case analysis.

---

31. Complexity of Functions

Suppose:

void function1()
{
    // O(n)
}

void function2()
{
    // O(n²)
}

void main()
{
    function1();
    function2();
}

Total:

O(n) + O(n²)

Therefore:

O(n²)

06 • RECURSION

Recursion & Recurrence

32. Recursion and Time Complexity

Recursion requires special analysis.

Example:

void fun(int n)
{
    if(n == 0)
        return;

    fun(n-1);
}

There are n recursive calls.

Therefore:

Time = O(n)

---

33. Recursive Binary Search

Binary search divides the input by 2 in every recursive call.

Recurrence:

T(n) = T(n/2) + O(1)

Therefore:

T(n) = O(log n)

---

34. Merge Sort Recurrence

Merge Sort divides the array into two halves.

Recurrence:

T(n) = 2T(n/2) + O(n)

Result:

T(n) = O(n log n)

---

07 • ADVANCED

Master Theorem

35. Master Theorem

The Master Theorem is used to solve many divide-and-conquer recurrences.

General form:

T(n) = aT(n/b) + f(n)

Where:

  • a = number of recursive subproblems
  • n/b = size of each subproblem
  • f(n) = work outside recursion

Define:

p = log_b(a)

Compare:

f(n)

with:

n^p

---

36. Master Theorem — Case 1

If:

f(n) = O(n^(p-ε))

for some ε > 0, then:

T(n) = Θ(n^p)

Example:

T(n) = 2T(n/2) + O(1)

Here:

a = 2
b = 2

p = log₂2 = 1

So:

T(n) = Θ(n)

---

37. Master Theorem — Case 2

If:

f(n) = Θ(n^p log^k n)

then:

T(n) = Θ(n^p log^(k+1)n)

Example:

T(n) = 2T(n/2) + Θ(n)

Here:

p = 1

and:

f(n) = Θ(n)

Therefore:

T(n) = Θ(n log n)

This is the Merge Sort recurrence.

---

38. Master Theorem — Case 3

If:

f(n) = Ω(n^(p+ε))

and the regularity condition holds, then:

T(n) = Θ(f(n))

This is useful when the non-recursive work dominates the recursive part.

08 • SPACE ANALYSIS

Space Complexity

39. Space Complexity

Space complexity measures how much memory an algorithm requires as the input grows.

Memory can include:

  • variables
  • arrays
  • objects
  • recursion stack
  • dynamically allocated memory
  • auxiliary data structures

---

40. Input Space vs Auxiliary Space

This distinction is very important.

Input Space

Memory required to store the input itself.

Example:

int arr[n];

If the array is part of the input:

Input Space = O(n)

Auxiliary Space

Extra memory used by the algorithm apart from the input.

For example, an algorithm may receive an array but use another temporary array of size n.

Then:

Auxiliary Space = O(n)

---

41. Constant Space — O(1)

int sum = 0;
int max = 0;

Only a fixed number of variables are used.

Therefore:

Space Complexity = O(1)

---

42. Linear Space — O(n)

int temp[n];

Memory grows with n.

Therefore:

Space Complexity = O(n)

---

43. Two-Dimensional Space — O(n²)

For:

int matrix[n][n];

Number of elements:

n × n = n²

Therefore:

Space Complexity = O(n²)

---

44. Recursion and Space Complexity

Consider:

void fun(int n)
{
    if(n == 0)
        return;

    fun(n-1);
}

There can be n active stack frames.

Therefore:

Auxiliary Space = O(n)

Even though the function doesn't create an array, recursion uses the call stack.

09 • DESIGN

Time-Space Tradeoff & Amortized Analysis

46. Time-Space Tradeoff

Sometimes we use extra memory to make an algorithm faster.

This is called:

Time-Space Tradeoff

Example

Suppose we repeatedly search for values.

Using a hash table may require:

Extra Space = O(n)

but can provide approximately:

Average Search Time = O(1)

So:

More memory
      ↓
Faster operations

This is a common design principle.

---

47. Array vs Hash Table Example

Suppose we need to check whether an element exists.

Linear Search

Time  = O(n)
Space = O(1)

Hash Table

Typically:

Average Time = O(1)
Space        = O(n)

We traded memory for speed.

51. Amortized Analysis

Amortized analysis studies the average cost of operations over a sequence of operations.

It is different from average-case analysis.

Example: Dynamic Array

Normally adding an element:

O(1)

But when the array becomes full, it may resize and copy all elements:

O(n)
Although one particular insertion can cost O(n), over a long sequence of insertions, the amortized insertion cost is typically:
O(1)

---

52. Aggregate Analysis

In aggregate analysis, we calculate the total cost of a sequence of operations and divide by the number of operations.

Example:

n insertions

Suppose total cost is proportional to:

2n

Then:

2n / n = 2

Therefore amortized cost:

O(1)

---

53. Worst-Case vs Amortized Complexity

Do not confuse these.

Worst Case

Looks at the most expensive individual operation.

Amortized

Looks at the total cost over a sequence of operations.

Example:

Dynamic array:

One resize → O(n)
Amortized insertion → O(1)

10 • FUNDAMENTALS

Analysis Rules & Simplification

54. Logarithm Bases in Complexity

You may see:

log₂ n
log₁₀ n
ln n

In Big-O analysis, the base usually doesn't matter.

Why?

Using the change-of-base formula:

log₂ n = log₁₀ n / log₁₀ 2

The denominator is a constant.

Therefore:

O(log₂ n) = O(log₁₀ n) = O(log n)

---

55. Dropping Constants

Suppose:

T(n) = 5n

We write:

O(n)

Not:

O(5n)

Because constant multipliers do not change the asymptotic growth class.

Similarly:

O(100n²) = O(n²)

---

56. Dropping Lower-Order Terms

Suppose:

T(n) = n² + n + 10

The dominant term is:

n²

Therefore:

O(n²)

Similarly:

n³ + n² + n + 1

becomes:

O(n³)

---

57. Important Rules for Complexity Analysis

Rule 1 — Sequential Statements

Add complexities:

O(n) + O(n²)

Result:

O(n²)

---

Rule 2 — Nested Loops

Usually multiply:

O(n) × O(n)

Result:

O(n²)

---

Rule 3 — Constants

Ignore constants:

O(5n) → O(n)

---

Rule 4 — Lower Terms

Ignore lower-order terms:

O(n² + n) → O(n²)

---

Rule 5 — Logarithmic Loops

If the variable doubles or halves:

O(log n)

---

Rule 6 — Different Variables

Keep independent variables:

O(nm)

Do not automatically convert it to:

O(n²)

Searching, Sorting & Data Structures

58. Common Mistakes

Mistake 1

Thinking:

for loop = always O(n)

Not always.

If:

i = i * 2

then:

O(log n)

---

Mistake 2

Thinking nested loops are always O(n²).

Example:

for(i = 0; i < n; i++)
{
    for(j = 0; j < 10; j++)
    {
    }
}

Inner loop is constant.

Therefore:

O(n × 10)
= O(n)

---

Mistake 3

Ignoring recursion stack.

A recursive algorithm may have:

Time = O(n)
Space = O(n)

because of recursive calls.

---

Mistake 4

Confusing input space with auxiliary space.

Always identify whether the memory is:

Input storage

or:

Extra memory

Consider:

for(int i = 1; i <= n; i++)

    }

O(log n)

    }

n + (n-1) + (n-2) + ... + 1

n(n+1)/2

O(n) + O(m)

O(n + m)

    {
        sum += arr[i];
    }

Additional variables:

sum
i

Only a constant number of variables.

Therefore:

Auxiliary Space = O(1)

O(n)

64. Recursive Space Example

void print(int n)
{
    if(n == 0)
        return;

    printf("%d", n);
    print(n-1);
}

There are approximately n active calls.

Therefore:

Time = O(n)
Space = O(n)

because of the recursion stack.

---

65. Complexity of Binary Search

Binary search repeatedly divides the search area by 2.

Suppose:

n = 1,000,000

After each step:

1,000,000
500,000
250,000
125,000
...
1

Approximately:

log₂(1,000,000)
≈ 20 comparisons.

This is why binary search is much faster than linear search for large sorted arrays.

---

66. Complexity of Merge Sort

Merge Sort follows:

Divide
   ↓
Sort left
   ↓
Sort right
   ↓
Merge

Recurrence:

T(n) = 2T(n/2) + O(n)

There are:

log n

levels.

At every level, approximately:

O(n)

work is performed.

Therefore:

Time = O(n log n)

Extra array space:

Space = O(n)

---

67. Complexity of Quick Sort

Quick Sort selects a pivot.

Balanced partition

T(n) = 2T(n/2) + O(n)

Therefore:

Average = O(n log n)

Bad partition

If pivot repeatedly becomes the smallest/largest element:

T(n) = T(n-1) + O(n)

Therefore:

Worst Case = O(n²)

---

68. Complexity of Binary Tree Traversal

Suppose a binary tree has n nodes.

During traversal:

Each node is visited once.

Therefore:

Time = O(n)

Recursive traversal also uses stack space.

For a skewed tree:

Space = O(n)

For a balanced tree:

Space = O(log n)

Complexity depends on implementation.

O((V + E) log V)

For sparse graphs, the heap-based implementation is often more efficient.

74. Exam-Oriented Definitions

Time Complexity

Time complexity is the rate at which the running time or number of basic operations of an algorithm grows with respect to input size.

Space Complexity

Space complexity is the amount of memory required by an algorithm as a function of input size.

Big-O

Big-O notation represents an asymptotic upper bound on an algorithm's growth rate.

Big-Omega

Big-Omega represents an asymptotic lower bound.

Big-Theta

Big-Theta represents a tight asymptotic bound.

Time-Space Tradeoff

Time-space tradeoff is the technique of using additional memory to reduce computation time, or reducing memory at the cost of additional computation.

76. How to Analyze Any Algorithm

Follow these steps:

Step 1

Identify the input size.

n = input size

Step 2

Find the basic operation.

Example:

comparison
assignment
addition

Step 3

Count how many times it executes.

Step 4

Identify loops.

One loop → usually O(n)
Nested loops → usually O(n²)
Doubling/halving → O(log n)

Step 5

Check recursion.

Look at:

Number of recursive calls

and:

Size of each subproblem

Step 6

For space, count extra memory.

Check:

arrays
objects
temporary variables
recursion stack

Step 7

Remove constants.

O(5n) → O(n)

Step 8

Remove lower-order terms.

O(n² + n) → O(n²)

78. Final Takeaway

The most important thing to understand is:

Complexity is about growth, not exact running time.

An algorithm that works perfectly for:

n = 10

may become unusable for:

n = 1,000,000

Therefore, in DSA we try to design algorithms with smaller growth rates.

The most important complexity classes to remember are:
