01 • FOUNDATION

What is Complexity?

Definition: Complexity analysis studies how the computational resources required by an algorithm grow as the input size increases.

For DSA, the two most important resources are time and space.

TimeHow much computational work?
SpaceHow much memory?
nInput size
GrowthHow cost changes with n

Why do we need it?

Two algorithms can produce the same answer but have very different performance. Complexity lets us compare them without depending on a particular computer, programming language or exact clock time.

Example: Searching Linear search may inspect up to n elements, while binary search on sorted data repeatedly halves the search range. Their typical growth is O(n) and O(log n).
02 • FUNDAMENTALS

Input Size and Basic Operations

Input size is normally represented by n.

ProblemTypical Input Size
ArrayNumber of elements = n
StringNumber of characters = n
n × n matrixNumber of elements = n²
GraphVertices V and edges E

Basic Operation

A basic operation is a fundamental unit of work such as comparison, assignment, arithmetic operation, array access or pointer update. 

int x = a + b;

We do not normally count every machine instruction. We count operations in a way that captures how their number grows with the input.

03 • PERFORMANCE

Algorithm Efficiency

Algorithm efficiency describes how much time and memory an algorithm needs as the input size becomes larger.

Important idea

  • A fast algorithm is not necessarily memory-efficient.
  • A memory-efficient algorithm may perform more computation.
  • We compare growth rates rather than exact seconds.
  • For large inputs, the growth rate becomes especially important.
Remember: Complexity is about scalability — how the algorithm behaves when n becomes very large.
04 • TIME

Time Complexity

Definition: Time complexity describes how the number of basic operations performed by an algorithm grows with input size n. It is not necessarily the exact number of seconds on a clock.

O(1) — Constant Time

int x = arr[5];

A direct array access takes approximately the same amount of work regardless of n.

Time = O(1)

O(log n) — Logarithmic Time

for(int i = 1; i < n; i = i * 2)
{
    // operation
}

The value doubles each iteration: 1, 2, 4, 8, ... n.

Number of iterations ≈ log₂(n) → O(log n)

O(n) — Linear Time

for(int i = 0; i < n; i++)
{
    printf("%d", arr[i]);
}

The loop executes n times.

n operations → O(n)

O(n log n) — Linearithmic Time

Common in efficient divide-and-conquer sorting algorithms. The problem has approximately log n levels and about n work per level.

n × log n → O(n log n)

O(n²) — Quadratic Time

for(int i = 0; i < n; i++)
{
    for(int j = 0; j < n; j++)
    {
        printf("*");
    }
}
n × n = n² → O(n²)

O(n³) — Cubic Time

for(int i = 0; i < n; i++)
    for(int j = 0; j < n; j++)
        for(int k = 0; k < n; k++)
            printf("*");
n × n × n = n³ → O(n³)

O(2ⁿ) — Exponential

Naive recursive Fibonacci is a classic example. The number of recursive calls grows very rapidly as n increases.

Naive Fibonacci ≈ O(2ⁿ)

O(n!) — Factorial

Generating every permutation of n elements produces n! possibilities. Factorial growth becomes impractical very quickly.

Number of permutations = n! → O(n!)
05 • ANALYSIS

Best Case, Average Case and Worst Case

Best Case

The input that causes the algorithm to perform the minimum amount of work.

Worst Case

The input that causes the maximum amount of work.

Average Case

The expected cost over a specified distribution of possible inputs.

Linear Search Search for 10 in [10, 20, 30, 40, 50] → best case O(1).
Search for the last element or a missing element → worst case O(n).
Under a simple uniform model, average work is proportional to n, so O(n).
Exam point: Big-O, Ω and Θ are mathematical bounds. They are not technically synonyms for worst, best and average case.
06 • MEMORY

Space Complexity

Definition: Space complexity describes how the memory requirement of an algorithm grows with input size.

O(1) Space

int sum = 0;
int max = 0;
int i = 0;

A fixed number of variables is used.

O(n) Space

int temp[n];

Memory grows linearly with n.

O(n²) Space

int matrix[n][n];

The number of stored elements is n².

Recursion Stack

void fun(int n)
{
    if(n == 0) return;
    fun(n - 1);
}

There can be n active calls, so the recursion stack uses O(n) auxiliary space.

07 • MEMORY BREAKDOWN

Input Space vs Auxiliary Space

Input Space

Memory required to store the input itself.

Auxiliary Space

Extra memory used by the algorithm beyond the input.

Example If an algorithm receives an array of n elements and creates another temporary array of n elements, the input occupies O(n), while the auxiliary space is O(n).
SituationAuxiliary Space
Fixed variablesO(1)
Temporary array of n elementsO(n)
n × n temporary matrixO(n²)
n recursive stack framesO(n)
08 • MATHEMATICAL ANALYSIS

Asymptotic Notations — O, Ω and Θ

Big-O — O()

Big-O gives an asymptotic upper bound on growth.
Example f(n) = 3n² + 5n + 10 → O(n²), because n² dominates for large n.

Big-Omega — Ω()

Big-Omega gives an asymptotic lower bound on growth.

Big-Theta — Θ()

Big-Theta gives a tight asymptotic bound: the function grows within the same order from both upper and lower sides.
NotationMeaningEasy Memory Trick
O(f(n))Upper boundAt most this growth order
Ω(f(n))Lower boundAt least this growth order
Θ(f(n))Tight boundSame growth order

Dropping Constants

O(5n) = O(n)

Dropping Lower-Order Terms

O(n² + n + 10) = O(n²)
Important: The dominant growth term determines the asymptotic class.

10 • PROBLEM SOLVING

How to Analyze Loops

Single Loop

for(int i = 0; i < n; i++)
{
    // O(1)
}
n iterations → O(n)

Two Sequential Loops

for(int i = 0; i < n; i++) { }

for(int j = 0; j < n; j++) { }
O(n) + O(n) = O(2n) = O(n)

Nested Loops

for(int i = 0; i < n; i++)
    for(int j = 0; j < n; j++) { }
n × n = O(n²)

Doubling Loop

for(int i = 1; i < n; i *= 2) { }
1, 2, 4, 8, ... → O(log n)

Halving Loop

for(int i = n; i > 0; i /= 2) { }
n, n/2, n/4, ... → O(log n)

Dependent Nested Loop

for(int i = 0; i < n; i++)
    for(int j = 0; j < i; j++) { }

Total work is:

0 + 1 + 2 + ... + (n - 1) = n(n - 1)/2 = O(n²)

Different Variables

for(int i = 0; i < n; i++) { }

for(int j = 0; j < m; j++) { }
O(n + m), not automatically O(n²)
Common mistake: Nested loops are not always O(n²). If the inner loop is constant, the total may still be O(n).
11 • RECURSION

Recursion and Complexity

Recursive algorithms call themselves on smaller inputs. Analyze both the number of calls and the work done at each call.

Linear Recursion

void fun(int n)
{
    if(n == 0)
        return;

    fun(n - 1);
}
T(n) = T(n - 1) + O(1) → O(n)
Recursion stack → O(n) space

Binary Search Recursion

T(n) = T(n/2) + O(1) → O(log n)

Naive Fibonacci

int fib(int n)
{
    if(n <= 1) return n;
    return fib(n-1) + fib(n-2);
}

Each call can generate two more calls, producing exponential growth.

Time ≈ O(2ⁿ)
Remember: Recursion can affect both time and space because every active function call occupies a stack frame.
12 • ADVANCED

Recurrence Relations

A recurrence describes the running time of a recursive algorithm in terms of the running time of smaller inputs.

Example 1 — Linear Recursion

T(n) = T(n - 1) + O(1)

Expanding repeatedly gives n levels.

T(n) = O(n)

Example 2 — Binary Search

T(n) = T(n/2) + O(1) → O(log n)

Example 3 — Merge Sort

T(n) = 2T(n/2) + O(n) → O(n log n)
13 • ADVANCED ANALYSIS

Master Theorem

Master Theorem is a standard method for solving many divide-and-conquer recurrences of the form T(n) = aT(n/b) + f(n).

General Form

T(n) = aT(n/b) + f(n)
  • a = number of recursive subproblems
  • b = factor by which input size is reduced
  • f(n) = work outside the recursive calls

Case 1

If f(n) grows polynomially slower than n^(log_b a), then:

T(n) = Θ(n^(log_b a))

Case 2

If f(n) has the same polynomial order as n^(log_b a), a logarithmic factor is added.

T(n) = Θ(n^(log_b a) log n)

Case 3

If f(n) grows polynomially faster than n^(log_b a), and the regularity condition is satisfied:

T(n) = Θ(f(n))
Merge Sort T(n) = 2T(n/2) + Θ(n)
a = 2, b = 2, log₂2 = 1, f(n) = Θ(n)
Therefore → Θ(n log n)
14 • DESIGN PRINCIPLE

Time-Space Tradeoff

Time-space tradeoff means using additional memory to reduce computation time, or saving memory at the cost of additional computation.
More Space ↔ Less Time    |    Less Space ↔ More Time
Example: Hash Table Repeatedly scanning an array can take O(n) per search. A hash table typically uses O(n) storage and can provide O(1) average lookup.
15 • ADVANCED

Amortized Analysis

Amortized analysis studies the average cost of operations over a sequence of operations. It does not mean probabilistic average-case analysis.

Dynamic Array Example

Most insertions at the end can be O(1). Occasionally, when the array is full, resizing and copying can cost O(n). Over many insertions, the amortized cost per insertion is typically O(1).

ViewCost
One resize operationO(n)
Typical appendO(1)
Amortized appendO(1)

20 • SOLVED ANALYSIS

Important Solved Examples

Example 1 — Three Nested Loops

for(int i = 0; i < n; i++)
{
    for(int j = 0; j < n; j++)
    {
        for(int k = 0; k < n; k++)
        {
            // O(1)
        }
    }
}
n × n × n = O(n³)

Auxiliary space is O(1) if no additional input-sized structure is created.

Example 2 — Logarithmic Outer Loop

for(int i = 1; i < n; i *= 2)
{
    for(int j = 0; j < n; j++)
    {
        // O(1)
    }
}
O(log n) × O(n) = O(n log n)

Example 3 — Sequential Different Inputs

for(int i = 0; i < n; i++) { }

for(int j = 0; j < m; j++) { }
O(n) + O(m) = O(n + m)

Example 4 — Dominant Term

T(n) = 3n² + 7n + 100

Ignore the constant multiplier and lower-order terms.

T(n) = O(n²)

Example 5 — Summation

for(int i = 0; i < n; i++)
{
    for(int j = 0; j < i; j++)
    {
        // O(1)
    }
}

Total work:

0 + 1 + 2 + ... + (n - 1) = n(n - 1)/2 = O(n²)
Exam method: First identify the input variable, then count iterations, write the mathematical expression, and finally simplify it to asymptotic form.

Most Important Rules

  • Sequential blocks → add their complexities.
  • Nested loops → usually multiply iteration counts.
  • Doubling or halving → usually O(log n).
  • Drop constant multipliers.
  • Drop lower-order terms.
  • Keep different input variables separate, such as O(n + m).
  • Always consider recursion-stack space.
  • Separate input space from auxiliary space when asked.

Most Important Definitions

  • Time Complexity: Growth of computational work with input size.
  • Space Complexity: Growth of memory requirement with input size.
  • Big-O: Asymptotic upper bound.
  • Big-Omega: Asymptotic lower bound.
  • Big-Theta: Tight asymptotic bound.
  • Time-Space Tradeoff: Trading memory for computation time or vice versa.
  • Amortized Analysis: Average cost over a sequence of operations.
