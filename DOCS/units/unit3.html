01 • BASICS

Tree Terminology

Definition: A tree is a non-linear hierarchical data structure made of nodes connected by edges. It has a root node and zero or more child nodes.

Simple Example

              A
            /   \
           B     C
         /  \     \
        D    E     F

Important Terms

  • Node: Each element of a tree is called a node.
  • Root: The topmost node. Here, A is the root.
  • Edge: The connection between two nodes. A-B is an edge.
  • Parent: A node that has one or more children.
  • Child: A node directly connected below a parent.
  • Siblings: Nodes having the same parent.
  • Leaf: A node having no children.
  • Internal Node: A node having at least one child.
  • Degree of Node: Number of children of that node.
  • Degree of Tree: Maximum degree of any node in the tree.
  • Depth: Number of edges from root to a node.
  • Height: Maximum depth of any node, when height is measured in edges.
  • Subtree: A tree formed by a node and all of its descendants.

Example Analysis

For the tree above A = root
B and C = children of A
D and E = children of B
F = child of C
D, E and F = leaf nodes
B and C = siblings
For a tree with n nodes: Number of edges = n − 1
Exam note: Some books count the root as level 0 while others count it as level 1. Follow the convention given in the question or your class notes.
02 • MOST IMPORTANT

Binary Tree

Definition: A binary tree is a tree in which every node has at most two children. These children are called the left child and right child. 
          10
        /    \
       20     30
      /  \
     40   50

Notice that a node may have 0, 1 or 2 children. It does not have to have exactly two children.

Maximum Nodes

If root is at level 0, maximum nodes at level i are:

Maximum nodes at level i = 2ⁱ

Maximum nodes in a binary tree of height h:

Maximum nodes = 2^(h+1) − 1
Example If h = 2:
Maximum nodes = 2³ − 1 = 7

Binary Tree Node in C

Basic Node Structure
struct Node
{
    int data;
    struct Node *left;
    struct Node *right;
};
Remember: Binary Tree = maximum 2 children = Left + Right.
03 • REPRESENTATION

Tree Representation

Binary trees can commonly be represented using:

  • Array representation
  • Linked representation

Array Representation

          A
        /   \
       B     C
      / \
     D   E

Using 1-based indexing:

Index:  1  2  3  4  5
Data:   A  B  C  D  E
Left Child = 2i
Right Child = 2i + 1
Parent = floor(i / 2)

Linked Representation

struct Node
{
    int data;
    struct Node *left;
    struct Node *right;
};

Each node stores data and two pointers:

       +---------+
       |  data   |
       +---------+
       |  left   | ----> left child
       +---------+
       |  right  | ----> right child
       +---------+
Array Linked Representation
Uses indexes Uses pointers
Very suitable for complete trees Suitable for irregular trees
Can waste space for sparse trees Dynamic memory allocation
Parent/child positions are calculated Connections are stored through pointers
04 • TREE TYPES

Important Types of Binary Trees

Full / Strict Binary Tree

Every node has either 0 children or 2 children. A node cannot have exactly one child. 
        A
       / \
      B   C
     / \
    D   E

Perfect Binary Tree

Every internal node has exactly two children and all leaf nodes are at the same level. 

          A
        /   \
       B     C
      / \   / \
     D   E F   G

Skewed Binary Tree

A tree where nodes mostly extend in one direction.

      A
       \
        B
         \
          C
           \
            D
05 • VERY IMPORTANT

Complete Binary Tree

A complete binary tree has every level completely filled except possibly the last level, and the last level is filled from left to right. 
          A
        /   \
       B     C
      / \   /
     D   E F

This is complete because the last level is filled from left to right.

Not Complete

          A
        /   \
       B     C
        \   /
         E F

This is not complete because an earlier left position is empty while a later position is occupied.

Shortcut: Complete Binary Tree = levels filled + last level left to right.
06 • EXTENDED TREE

Extended Binary Tree

An extended binary tree represents missing/null children by special external nodes. Thus, each internal node can be viewed as having exactly two children. 
          A
        /   \
       B     C
      / \   / \
     X   X X   X

X = External / Null node

The main idea is to replace missing child links with explicit external nodes. This representation is useful in theoretical analysis and expression-tree concepts.

Don't confuse: Complete means about how positions are filled. Extended means missing children are represented using external nodes.
07 • APPLICATION

Expression Tree

An expression tree is a binary tree used to represent an arithmetic or logical expression. Operators are internal nodes and operands are leaf nodes.

Example

Expression:

A + B × C

Because multiplication has higher precedence:

A + (B × C)
          +
        /   \
       A     *
            / \
           B   C

Important Rule

  • Operators → internal nodes
  • Operands → leaf nodes
Traversal Expression Form Result
Inorder Infix A + B * C
Preorder Prefix + A * B C
Postorder Postfix A B C * +
08 • CORE CONCEPT

Tree Traversal

Traversal means visiting every node of a tree exactly once in a systematic order.

The three important depth-first traversals are:

  • Inorder → Left, Root, Right → LNR
  • Preorder → Root, Left, Right → NLR
  • Postorder → Left, Right, Root → LRN
             A
           /   \
          B     C
         / \   / \
        D   E F   G
Memory trick:
Pre = Root first → NLR
In = Root in middle → LNR
Post = Root last → LRN
09 • TRAVERSAL

Inorder Traversal

Rule: Left → Root → Right (LNR)
             A
           /   \
          B     C
         / \   / \
        D   E F   G

Step-by-Step

  1. Go to the left subtree.
  2. Visit the root.
  3. Go to the right subtree.
Inorder = D B E A F C G
Special point: In a Binary Search Tree, inorder traversal gives the keys in sorted order.
10 • TRAVERSAL

Preorder Traversal

Rule: Root → Left → Right (NLR)
             A
           /   \
          B     C
         / \   / \
        D   E F   G

Step-by-Step

  1. Visit the root.
  2. Traverse the left subtree.
  3. Traverse the right subtree.
Preorder = A B D E C F G
Expression Tree Connection Preorder of an expression tree gives its prefix notation.
11 • TRAVERSAL

Postorder Traversal

Rule: Left → Right → Root (LRN)
             A
           /   \
          B     C
         / \   / \
        D   E F   G

Step-by-Step

  1. Traverse the left subtree.
  2. Traverse the right subtree.
  3. Visit the root at the end.
Postorder = D E B F G C A
Expression Tree Connection Postorder of an expression tree gives its postfix notation.
12 • PROBLEM SOLVING

Constructing a Binary Tree from Traversals

A binary tree can be constructed when suitable traversal sequences are given, such as preorder + inorder.

Example

Given Preorder = A B D E C F G
Inorder = D B E A F C G

Step 1 — Find Root

The first element of preorder is the root.

Root = A

Step 2 — Split Inorder

Inorder:
D B E | A | F C G
       Left  Root  Right

So D-B-E belongs to the left subtree and F-C-G belongs to the right subtree.

Final Tree

             A
           /   \
          B     C
         / \   / \
        D   E F   G
Exam method: Preorder gives the root. Inorder tells which elements belong to the left and right subtrees. Repeat the same process recursively.
13 • ADVANCED TREE

Threaded Binary Tree

A threaded binary tree uses otherwise NULL child pointers to store links called threads. These threads can point to an inorder predecessor or inorder successor.

Why Threading?

In an ordinary binary tree, many pointers may be NULL:

        A
       / \
      B   C

B.left  = NULL
B.right = NULL
C.left  = NULL
C.right = NULL

Threading uses some of these NULL links to make traversal easier.

Inorder Example

Inorder = B A C

If B has no right child, its right pointer can be used as a thread to its inorder successor A.

Types

Type Meaning
Single Threaded Threads are used in one direction, such as right threads.
Double Threaded Both left and right NULL links may be used as predecessor/successor threads.
Main idea: NULL pointer → useful thread → predecessor or successor.
14 • IMPORTANT ALGORITHM

Huffman Algorithm

Huffman coding is a lossless compression technique that creates variable-length prefix codes. More frequent symbols generally receive shorter codes.

Given Frequencies

A = 5
B = 9
C = 12
D = 13
E = 16
F = 45

Step 1 — Pick Two Smallest

5 + 9 = 14

New list:

12, 13, 14, 16, 45

Step 2

12 + 13 = 25

New list:

14, 16, 25, 45

Step 3

14 + 16 = 30

New list:

25, 30, 45

Step 4

25 + 30 = 55

New list:

45, 55

Step 5 — Final Root

45 + 55 = 100

General Huffman Procedure

  1. Arrange all symbols according to their frequencies.
  2. Pick the two symbols/nodes having the smallest frequencies.
  3. Combine them into a new node whose frequency is their sum.
  4. Insert the new node back into the list.
  5. Repeat until only one node remains.
  6. Assign binary labels such as 0 and 1 to branches.
  7. The path from root to a symbol gives its Huffman code.

Prefix Code

In a prefix code, no complete codeword is the prefix of another codeword. This makes decoding unambiguous.
Exam shortcut: Always select the two smallest frequencies first. Combine → reinsert → repeat.
Important: If two frequencies are equal, different valid tie choices can produce different-looking trees/codes while maintaining the Huffman optimality property.
15 • EXAM REVISION

Complexity & Key Facts

Traversal O(n)
Array Child O(1)
Tree Space O(n)
Huffman Typically O(n log n)

Important Formulas

Edges in a tree = n − 1
Maximum nodes at level i = 2ⁱ
Maximum nodes at height h = 2^(h+1) − 1
Left child in 1-based array = 2i
Right child in 1-based array = 2i + 1
Parent in 1-based array = floor(i/2)
